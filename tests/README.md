# 回帰テスト

## React のローカル編集確認

`node tests/admin-save.cjs` は保存通信の単体テストです。POST本文・nonce・全解除と、
HTTPエラー・通信失敗・不正な成功応答を検証します。実HTTPやデータベースへの書き込みは行いません。
保存中の入力ロック、二重送信防止、成功後の未保存表示解除、失敗時の入力保持は実画面でも確認してください。

`WP_ROOT=/path/to/wordpress node tests/admin-local-edit.cjs` でブラウザのスモークテストを実行できます。
事前に `npm run build:admin` を実行してください。Playwrightのブラウザが必要です。
インストール済みChromeを使う場合は `PLAYWRIGHT_CHANNEL=chrome` を指定します。
PHPの実データ定義を使い、HTTP取得はモックします。実サイトへの保存・通信は行いません。
デスクトップ／モバイル幅で全解除、タブ間の編集保持、再読み込み時の復元、保存通信が発生しないことを確認します。
プレビュー通信は未変換の例文を返すモックであり、変換内容はPHPの回帰テストで検証します。
`node tests/admin-preview.cjs` はプレビュー通信の本文、応答形式、不正応答、通信失敗、中止を検証します。
実画面では連続変更時の最新結果、読み込み・失敗表示、再試行も確認してください。
このテストはWordPress全体の管理画面・認証の検証ではありません。

プラグイン直下で実行します。追加のテストライブラリは不要です。
初回およびクラスの追加・移動後は `composer autoload:runtime` を実行してください。
`vendor-dev/` は開発ツール用、`vendor/` はプラグイン実行用です。
後者は開発依存を含めず生成するため、PHP 7.4 でも起動できます。

```sh
WP_ROOT="/path/to/wordpress" composer test
```

`WP_ROOT` は `wp-includes` を含む WordPress 6.8 以降のディレクトリです。
Composer を使わない場合も同じテストを実行できます。

```sh
WP_ROOT="/path/to/wordpress" php tests/run.php
```

成功時は `PASS` と検証数、PHP・WordPress のバージョンを表示します。
失敗時は `FAIL` と期待値・実際の値などを表示し、終了コード 1 を返します。
PHP の警告もテスト失敗として扱います。テストは CLI 専用です。

## 構成

- `integration/settings-rest.php`: GET/POST 登録、権限コールバック、JSON 本文の検証、保存とエラー応答。

## 設定 REST API

- GET `/wp-json/rubymaco/v1/settings` は初期データを返す。
- POST は Content-Type: application/json で4項目を直接送信する（settings で包まない）。
- 成功時は `{"settings": {...}}` を返す。検証失敗は400、非JSONは415、保存失敗は500。
- 500の保存失敗では一部が保存済みの場合がある。
- POST `/wp-json/rubymaco/v1/settings/preview` は同じ4項目を受け取り、保存せずに例文を変換する。任意の本文や追加項目は受け付けない。
- プレビュー応答は `{"previews":[{"id":"記法ID","examples":[{"text":"例文","html":"変換結果"}]}]}`。全記法を定義順で返し、選択された全ルールを各例文に適用する。全解除ならエスケープ済みの未変換例文を返す。
- 適用範囲は検証するがプレビュー結果には影響しない。傍点スタイル・描画方式は送信された値を使う。表示時にはプラグインの描画用CSSも必要。
- 全操作に manage_options が必要。管理画面は X-WP-Nonce に wp_rest nonce を送り、ユーザー言語には `?_locale=user` を指定する。
- Cookie/nonce 認証は WordPress 標準処理に委譲する。テストのルート登録・権限判定は代替処理で、実HTTP・Cookie・nonceの検証ではない。
- 実環境では未ログイン、権限のないユーザー、管理者の正常nonce・欠落nonce・不正nonce、言語切り替えを確認すること。

- `integration/settings-page-data.php`: 初期データの組み立て、リンク・画面文言、JSON 形式、設定変更の追従。翻訳は代替実装であり、実際の言語切り替えは画面で確認する。

- `integration/settings-definitions.php`: 表示定義の形式、値クラスとの対応、内部データの除外、互換設定の注意文。

- `integration/settings-service.php`: 設定値取得の形式、初期値、不正値、全解除、読み取り時に保存しないこと。

- `integration/post-content-filter.php`: 本文フィルタークラスの遅延登録・適用モード・変換・重複登録。

- `integration/bootstrap.php`: 起動時のフック・ショートコード登録、優先度、引数数、再起動時の重複。

- `unit/values.php`: 値クラスの候補、変換、不正値、共有インスタンス。
- `integration/conversion.php`: 全記法、HTML 保護、文字参照、両描画方式、再変換の抑止。
- `integration/multiple-rules.php`: 複数記法の適用順序、重なり、生成済み要素の保護、テキスト境界。
- `integration/settings.php`: 保存形式、初期値、全解除、不正値、各呼び出し元とプレビュー。
- `bootstrap.php`: WordPress の部分読み込みとテスト用の外部依存。

旧実装を正解として実行せず、固定の期待結果と重要な性質を検証します。
不具合修正時は、修正前には失敗するケースを該当ファイルへ追加してください。
`check_same()` は厳密比較を行います。

## 安全性と対象範囲

### 複数ルールの現行仕様

- 設定の選択順ではなく、レジストリの定義順に適用する。重複した選択は一度だけ扱う。
- 順序は二重山括弧の明示ルビ、同じ記法の漢字自動判定、丸括弧、rb、二重アンダースコア、mediawiki、傍点。
- 各ルールは直前のルールの変換結果を入力として使う。生成済みの ruby 要素と本プラグインの傍点要素の内部は変換しない。
- 記法は一つの対象テキストノード内で完結する必要がある。HTML 要素をまたいだ記法や、先行変換で分断された記法は変換しない。
- 例えば `《《漢字(かんじ)》》` は、丸括弧ルビを有効にすると内側だけがルビとなり、外側の `《《` と `》》` は残る。装飾の入れ子を保証する仕様ではない。
- `《《漢字《かんじ》《《強調》》` は、ルビ変換後に残ったテキストを再検索するため、後半の強調が傍点になる。元の全文から重複候補を捨てるだけの方式とは等価でない。
- 明示的に変換ルール配列を渡す API は、渡された配列順に従う。

これらは最適化前の現行挙動を固定するテストであり、重複記法の理想的な解釈を決めるものではない。
挙動を変える場合は、仕様変更として期待結果も見直す。

### テスト環境の範囲

`wp-load.php`、`wp-config.php`、データベース接続は読み込みません。
設定値はメモリ上の配列で扱い、書き込み用の関数は通常例外を投げます。
設定保存テスト中だけ update_option の代替処理を有効にし、メモリ上で更新・失敗を再現します。
実データベースへの接続や書き込みは行いません。
プラグイン本体を読み込むため、実際のクラス読み込み順も検証します。

HTML API、`esc_html()`、`esc_attr()`、`wp_kses()`、サニタイズ処理は
指定した WordPress の実装を使用します。設定取得、翻訳、URL、管理画面判定、
UTF-8 判定・文字コード名、許可プロトコルはテスト用の代替実装です。
そのため、実 DB への保存、翻訳、権限・nonce、ブラウザ表示、WordPress 全体の
起動や登録処理を保証するテストではありません。画面での確認も継続してください。

テストは PHP 7.4 で使える構文に限定していますが、対応バージョンの保証には
各 PHP と、それに対応する WordPress の組み合わせで実行する必要があります。
一つの環境での成功を全バージョンの検証済みとは扱いません。

既存の WPCS・PHPStan は本体のコードを対象とし、この軽量テストハーネスは対象外です。
`tests/` は `.distignore` により配布から除外します。
- `unit/autoload.php`: クラスの遅延読み込み・参照先と開発依存の分離。
